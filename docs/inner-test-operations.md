# 内测小包运营手册

这份文档用于第一批个人用户内测。当前目标不是做大平台，而是先稳定交付一个可售卖的小包：少量高质量视频、人工发账号、人工收集反馈、快速修正体验问题。

## 当前产品规则

- 免费体验视频：`part1-home-accommodation-001`、`part1-home-accommodation-002`、`part1-home-accommodation-003`
- 付费解锁视频：除以上三个视频以外的所有视频
- 账号范围：`ielts001` 到 `ielts200`
- 初始密码规则：账号后加 `pass`，例如 `ielts001 / ielts001pass`
- 当前登录状态：保存在用户浏览器本地，仅用于内测阶段的页面体验，不构成真正的付费权限保护
- 设备限制：当前不限制，同一账号可以多设备登录

## 人工发账号流程

1. 收款或确认赠送资格。
2. 从账号表里选择一个未发放账号。
3. 记录用户信息、发放时间、有效期和备注。
4. 把账号密码发给用户。
5. 引导用户打开网站，先看体验视频，再登录看付费内容。
6. 用户确认能登录后，把账号状态标记为“已发放”。

建议发给用户的话术：

```text
你的学习账号已开通：

账号：ielts001
密码：ielts001pass

打开学习页面后，点击右上角“登录”，登录成功后即可查看全部已开放视频。
建议先用手机和电脑各打开一次，确认视频、字幕、解析都能正常使用。
```

## 账号发放表字段

建议先用飞书表格或 Excel 管理，不需要一开始做完整后台。但如果开始正式收费，不能继续把账号密码和权限判断全部放在前端。

## 低成本账号方案

当前内测阶段可以继续使用前端账号，但要明确它只能降低误操作风险，不能防止用户绕过前端获取付费视频、字幕或解析内容。代码已经增加了本地登录状态校验和 30 天过期，但这不是安全边界。

正式收费前，推荐采用低成本的 Cloudflare Worker + KV/D1 方案：

1. 账号和密码只放在 Worker 或 D1，不放进前端 bundle。
2. 登录成功后由 Worker 返回短期 session cookie 或 token。
3. 付费视频通过 Worker 校验 session 后返回短期签名 URL。
4. 账号表继续用 Excel/飞书维护，定期导入账号状态、到期时间和停用状态。
5. 先不做复杂后台，只实现登录、有效期、停用和签名视频地址四项能力。

在服务端方案上线前，不要对外宣传“账号可以保护视频内容”；如果内容价值较高，应先控制用户规模并使用已获授权的素材。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 账号 | ielts001 | 发给用户的登录名 |
| 密码 | ielts001pass | 初始密码 |
| 状态 | 未发放 / 已发放 / 停用 | 当前账号状态 |
| 用户姓名 | 张三 | 可选 |
| 联系方式 | 微信备注名 | 避免记录过多隐私 |
| 收款状态 | 已收款 / 赠送 / 未收款 | 财务核对 |
| 开通日期 | 2026-07-06 | 发放当天 |
| 到期日期 | 2026-08-06 | 如果有有效期 |
| 备注 | 第一期内测用户 | 运营备注 |

## 视频上线验收清单

每个视频上线前，至少过一遍下面的检查。

- 标题：中英文标题准确，和目录页一致。
- 分类：雅思 Part 和话题分类正确。
- 视频：能正常加载、播放、暂停、拖动进度条。
- 字幕：时间基本对齐，当前句高亮不会明显错位。
- 翻译：中文自然，不逐字硬翻。
- 解析：只在值得讲的长句上出现，不要每句都堆解析。
- 地道表达：表达真实常用，能迁移到雅思口语。
- 表达页：移动端进入 `/lesson/:videoId/expressions` 后显示当前视频内容。
- 查词：点击英文单词能弹出词卡；查不到时提示友好。
- 手机端：微信内置浏览器、iPhone Safari、安卓浏览器至少抽测一种。
- 权限：三个免费视频可直接进入；其他视频未登录会跳转登录，登录后能进入。

## 第一批内测建议

- 人数控制在 5-20 人。
- 先不要承诺 30 个视频，先承诺“第一批持续更新”。
- 每个用户发放后，至少让他完成一个视频学习。
- 优先收集手机端反馈，因为真实用户大概率会在手机上学。
- 不要过早做自动支付和复杂后台，先把内容质量和学习体验打磨稳。

## 风险提醒

当前内容规划使用 YouTube 原视频。用于商业售卖时，优先采用官方嵌入、授权视频、Creative Commons 许可视频，或自有/购买授权素材。未获授权下载并重新托管公开视频，会带来版权和平台条款风险。
